Se configura un bridge de red en el host para que las VMs de QEMU tengan acceso directo a la red local, como si fueran máquinas físicas independientes.

### 1. Limpieza de Netplan (Evitar conflictos)

Primero, nos aseguramos de que Netplan no esté bloqueando a NetworkManager.

```Bash
# Respaldar y eliminar configuración vieja de Netplan
sudo mv /etc/netplan/50-cloud-init.yaml /etc/netplan/50-cloud-init.yaml.bak

# Aplicar para limpiar el estado actual
sudo netplan apply
```

### 2. Configuración del Bridge con NetworkManager (`nmcli`)

Estos comandos crean la infraestructura de red en tu host.

```Bash
# 1. Crear la interfaz virtual del puente (sin STP para rapidez)
sudo nmcli con add type bridge ifname br0 con-name br0 stp no

# 2. Desactivar la conexión física actual (Sustituye el nombre si es diferente)
# Esto te dejará sin internet unos segundos.
sudo nmcli con down "Wired connection 1"

# 3. Esclavizar la tarjeta física (enp9s0) al puente
sudo nmcli con add type bridge-slave ifname enp9s0 con-name br0-port master br0

# 4. Levantar el puerto y el puente
sudo nmcli con up br0-port
sudo nmcli con up br0
```

### 3. Comandos de Verificación (Estado del Host)

Para confirmar que el host tiene internet a través del puente:

```Bash
# Ver que br0 y br0-port estén en VERDE
nmcli con show

# Ver que br0 tenga la IP y enp9s0 NO tenga IP
ip addr show br0
ip addr show enp9s0

# Probar conexión
ping -c 3 8.8.8.8
```

### 4. Lanzamiento de QEMU y Conexión al Bridge

Para que la VM use el puente que creamos, debes ejecutar QEMU y luego "conectar el cable virtual".

**Paso A: Lanzar la VM**

```Bash
sudo qemu-system-x86_64 \
  -m 2G \
  -drive file=peer1.qcow2 \
  -netdev tap,id=net0,ifname=vmtap0,script=no,downscript=no \
  -device virtio-net-pci,netdev=net0,mac=52:54:00:12:34:56
```

**Paso B: Conectar la interfaz `vmtap0` al `br0` (En una nueva terminal del host)**

```Bash
# Meter la interfaz de la VM al puente
sudo ip link set vmtap0 master br0

# Levantar la interfaz virtual
sudo ip link set vmtap0 up
```

### 5. Resumen de Flujo Lógico (Para tu reporte/memoria)

1. **Host:** Deja de usar la IP directamente en la tarjeta física.
    
2. **Bridge:** Se convierte en el nuevo "gestor" de la IP del host.
    
3. **TAP (vmtap0):** Es el cable virtual que sale de la VM.
    
4. **Enlace:** Al unir `vmtap0` con `br0`, el router ve a la VM como si fuera otro cable físico conectado al switch de tu casa.
